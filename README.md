## 功能特性

- 🔑 **扫码登录**：番茄网页扫码登录，自动获取书架/进度/目录，无需手动配置 Cookie
- 📚 **书架管理**：浏览番茄小说，支持封面显示（统一收敛为**无签名** CDN 地址，杜绝签名过期导致的 403 空白）、4 种排序（最后阅读 / 书名 / 阅读进度 / 加入书架）与书名/作者关键字搜索
- 🏬 **书城浏览**：点开**直达书库列表**，顶部一排 **tab 栏**（男频 / 女频 / 榜单 / 搜索，原地切换），
  tab 正下方是一条**筛选行**（排序 / 状态 / 分类，等宽下拉胶囊「xx ▾」，点开选、选完原地刷新；
  条目少的**弹小窗**、条目多的才开全屏列表），
  免登录即可查看；**榜单共 30 项**（网页榜单 5 + **App 榜单 25**：
  男频 11 榜〔推荐/完本/阅读/高分/口碑/追更/热评/黑马/热搜/人气/巅峰〕、
  出版物 6 榜〔推荐/阅读/名著/收藏/新书/典藏〕、礼物榜 4 榜〔男/女频礼物榜、
  男/女频礼物·书籍〕）；列表**分页**（快翻到尾部自动预取下一页，操作框里也可手动「加载更多」），
  显示**连载中 / 已完结 / 已断更**状态与总章数（登录后经 `multidetail` 增强）；书籍详情页可一键「加入书架」「开始阅读」「章节目录」「下载」
- 📖 **章节阅读**：支持章节导航、自动翻页、目录自动跳转
- 🖼 **漫画支持**：漫画书（`book_type=1`）自动识别，逐页下载后**本机解密**（AES-256-GCM）并内联显示，无需任何配置
- 🔄 **进度同步**：自动同步阅读进度到服务器（进入阅读拉取 + **阅读中每 3 分钟定期上传**（档位可选 关闭 / 1 / 3 / 5 / 10 分钟）+ 章末/关文档/开目录即时上传；失败进待传队列并**落盘**，重启后继续补）
- ⚡ **预下载**：智能预下载后续章节，减少阅读等待；章节数可在设置页自选（关闭 / 1 / 3 / 5 / 10 / 20），优先级为「菜单选择 > config.lua > 内置默认」
- 💬 **段评功能**：正文中显示段评数字气泡，点击查看段评详情；可滚动评论列表，**图片内嵌**（自动下载后直接显示、**点图可全屏**，**HEIC 会转码成 WebP**，回填只重绘评论区自身、**不整屏闪**），评论支持**树状回复**（**点某条评论即可展开/收起那一条**，头行保留「回复N」计数，缩进显示层级、超长可续拉），底部按钮**固定两行**不随评论数增长，**字号跟着阅读字号走**（正文调大了评论区跟着大；
基准字号下限 18，比旧版固定 15 明显大一圈），开关常驻设置页
- 📡 **官方 App 协议**：正文/目录/书架统一走番茄 App reading 协议，设备身份本机自动注册，无需配置第三方聚合站
- ⬆️ **在线更新**：内置自更新器，菜单一键检查/下载/安装新版本（SHA-256 校验 + 自动备份回滚 + 国内镜像）
- 🎨 **界面优化**：适配墨水屏显示，纯黑白配色，无毛玻璃无平滑动画
- 📊 **阅读统计**：显示阅读进度（百分比/章节数）
- 📥 **批量下载**：支持下载全书，自动跳过已缓存章节；请求节流为「章间隔 1.0s + 随机抖动 0.6s + 每 20 章长休 6s」，对齐官方 App 协议的生产实现，可调可关
- 📋 **下载管理**：查看当前下载进度、取消任务、浏览历史记录
- 📶 **离线阅读**：书架和章节缓存持久化，无网络也可阅读已缓存内容
- 💾 **两层智能缓存**：书架/目录采用「内存主源 + 文件后备」策略，显示层零文件IO，刷新成功才更新缓存，失败保留旧数据
- ✨ **静默刷新**：进入阅读自动更新目录获取新章节，书架刷新动态更新内容无闪烁
- 🎛️ **操作菜单**：书架/目录左上角菜单图标，点击弹出操作选项（刷新书架 / 排序方式 / 搜索 关键字 / 显示方式）
- 🗂 **列表 / 封面网格**：书架和书城都能切成**封面网格**（封面 2:3），菜单左上角「显示方式」里
  切换、当场生效并记住；档位是**显式的「列×行」**（3×3 / 3×4 / 4×3 / 4×4），
  也能「自定义列×行…」（列 2~8、行 1~8，行填 0 或不填 = 按屏高自动）；格子四周留白、不贴边。
  **显示方式是各记各的**（列数 / 行数两边共用一份），切书城不会把书架也改成网格
- 📚 **阅读界面随时管书架**：阅读番茄书时，菜单 →「番茄小说」→ 书架动作项直接管**当前这本书**。
  文案**按实际状态给**（在架显示「移出书架」、不在架显示「加入书架」，不再把两个方向摆一起）；
  点进去仍会先查一次书架状态复核方向（在架时确认一次再移出）。重启 KOReader 后续读也照样可用
- 🔔 **读完退出时问一句**：不在书架的书，离开阅读时提示「要加入书架吗」——
  切章 / 换书不算离开，不会打扰；同一本书只问一次；书架状态未知时不猜方向、静默跳过
- 🧭 **阅读界面看得到「这本书是什么」**：菜单 →「番茄小说」→「**书籍信息**」，一屏看全
  书名 / 作者 / 分类 / 字数 / 状态 / 总章数与剩余未读 / 最近阅读 / 本地缓存 / 简介。
  从书架、书城打开时用内存里的完整记录；**重启后续读**也能从文档路径反推书号、
  再用**本地**书架缓存补全，全程不联网（不会点了菜单卡在网络等待上）
- 🔇 **章节末尾不再弹「已到文档末尾」**：番茄小说一章就是一个 html 文件，KOReader 会把
  「读完一章」当成「读完一本书」，于是读完最后一页再往后翻时会按它自己的
  「到达文档末尾时的操作」（默认弹窗询问）弹一个框。插件会在打开番茄章节期间把这一项
  **临时改成「什么都不做」**，离开时**还原你原来的选择** —— 读别的书（epub 等）行为完全不受影响

## 安装方法

1. 下载插件压缩包（从 GitHub Releases 页面）
2. 将 `fanqie.koplugin` 文件夹复制到 KOReader 的 `plugins/` 目录
3. 重启 KOReader
4. 在菜单中找到「番茄书架」入口
5. 首次使用扫码登录（菜单 → 番茄小说 → 扫码登录），用番茄小说 App 扫码即可

## 在线更新

菜单：**番茄小说 → 在线更新**

| 菜单项        | 说明                                  |
| ---------- | ----------------------------------- |
| **立即检查更新** | 手动检查。有新版会弹出更新说明与「下载并安装」确认框          |
| **自动检查更新** | 开关。开启时每次启动 KOReader 后延迟 5 秒静默检查一次   |
| **检查频率**   | 每天 / 每 3 天 / 每 7 天。限流用，避免每次启动都打网络   |
| **下载镜像**   | 自动（默认）/ 仅直连 GitHub / 四个预设镜像 / 自定义前缀 |
| **安装完成后**  | 询问是否重启（默认）/ 自动重启 / 稍后手动重启           |
| **当前版本**   | 只读展示                                |
| **回滚上次更新** | 仅在「装了但重启后没生效」时出现                    |

**关于安装**：升级会替换 `plugins/fanqie.koplugin/` 下的全部文件，但 **`config.lua` 会被保留**  
（Cookie 等凭证不用重填）。整个过程分四步，每一步失败都能安全收场：

1. 下载后**强制校验 SHA-256**（清单里带摘要，对不上直接拒绝安装）；
2. 解压到暂存目录，校验包结构（必须只含一个 `fanqie.koplugin` 根目录）与**包内版本号**     
   （必须与清单一致）；包里若出现 `config.lua` 直接拒绝；
3. 备份当前插件目录 → 替换文件 → 恢复 `config.lua`；中途任何一步失败都会自动回滚；
4. 重启 KOReader 后，插件启动时比对「期望版本 vs 实际运行版本」——一致才算更新成功并清掉     
   回滚点；不一致则保留备份，菜单里出现回滚入口。

**关于网络**：更新源是 GitHub Release。国内直连 `github.com` / `raw.githubusercontent.com`  
通常不通，插件会自动改用镜像（ghfast.top / gh-proxy.com / ghproxy.net / gh.ddlc.top）。  
镜像站按 IP 限流，换一个常能解决「检查更新失败」；镜像只影响下载速度，**不会影响安装内容**  
——下载完仍然强制校验 SHA-256。自动检查只在**已经联网**时进行，绝不主动开 WiFi。

⚠️ 有一个例外：「**更新清单不存在（HTTP 404）**」不是网络问题 —— 那是服务端确实没有这个文件
（这个版本还没发布，或者 `update.json` 没跟代码一起进 `main` 分支），**换哪个镜像都没用**
（所有镜像都指向同一个不存在的文件）。这种情况插件会单独把它列出来，不再混在
「换一个镜像试试」里。

**关于兼容性**：解压走 KOReader 自带的 `ffi/archiver`（纯 Lua），SHA-256 也是自带的纯 Lua 实现，  
因此**不依赖设备上有 `unzip` / `sha256sum` 命令**（Kindle 的 busybox 就没有）。

## 正文与段评来源

v2.4.0 起**移除多书源调度**（大灰狼/晴天聚合已下线），章节正文、段评、书架、目录全部走番茄官方协议：

- **正文/目录**：番茄 App 端 reading 协议（`api5-normal-sinfonlinec.fqnovel.com`）。请求前在本机生成设备画像、向 `log.snssdk.com` 注册换取 `device_id`/`install_id`，再经四神签名（X-Khronos / X-Ladon / X-Helios / X-Argus）请求密文并本地 AES 解密。设备身份每台设备独立生成并持久化，不复用他人身份；无需番茄账号登录。
- **书架/进度**：番茄网页接口，扫码登录获取 Cookie（见下节）。
- **段评**：番茄 App commentapi 协议（`/novel/commentapi/idea|comment|reply/list/...`），与正文同一套设备身份与签名，**无需大灰狼账号**。
- **漫画正文**：`book_type=1` 的书，章节正文是 JSON（`picInfos` 图片清单）而不是 HTML，插件按**内容嗅探**识别。    
  每页 CDN 返回的是 AES-256-GCM 密文，密钥取自章节 JSON 的 `encrypt_key`，在**本机**解密后再内联进章节 HTML；    
  落盘的每一张图都会与清单里的 `md5` 逐张校验（校验通过才认为下载成功）。

## 番茄官方扫码登录

番茄官方书源（书架/目录/进度）通过扫码登录获取 Cookie，**无需手动复制粘贴 Cookie 字符串**。

### 登录步骤

1. 菜单 → 番茄小说 → 扫码登录
2. 屏幕显示二维码
3. 打开手机番茄小说 App，扫描屏幕上的二维码
4. 在 App 中确认登录
5. 登录成功后 Cookie 自动持久化，重启 KOReader 也无需重新登录

### Cookie 过期

- Cookie 有效期较长（通常 60 天），过期后会提示重新登录
- 重新扫码即可，无需任何手动操作

### 手动 Cookie 保底（可选）

扫码登录是首选方式。如无法扫码（如设备无摄像头/网络受限），可手动填写 Cookie 作为 fallback：

- 在 `config.lua` 的 `cookie_string` 填入完整 Cookie 字符串（从浏览器开发者工具复制），或在 `cookies` 表里填入 `ttwid` / `sessionid` 等键值
- **优先级**：扫码 Cookie 优先；手动配置**只补齐本地缺失的键，不覆盖扫码结果**（v2.16.3 起）
- 清空扫码 Cookie（退出登录）后，手动配置整体生效

> ✅ **书城搜索只走免登录端点（v2.16.15）**：网页搜索接口认的是**风控标识 `s_v_web_id`** ——
> 它由浏览器安全 SDK **本地随机生成**，而服务端只认「它见过的那一串」
> （实测：把真值改 1 个字符、只换时间戳段、按算法严格自造，**一律 0 字节**；
> 同一轮拿真值当哨兵正常 ⇒ 不是限流），且**扫码登录链路不下发它**
> （登录页 / 二维码接口 / 首页 / 搜索页 / 书库全都不发）。
> ⇒ 对一个没在浏览器里打开过番茄的设备，网页搜索**永远**失败：每次都白打一次请求，
> 再弹一句「已改用免登录搜索」。所以 v2.16.15 起**网页搜索路径整块删除**，
> 搜索只走免签名端点（`novel.snssdk.com`，免签名 / 免 Cookie / 免风控标识）：
> **只扫码登录、甚至完全不登录，也能搜到书，且不再有任何提示弹窗**。
> 代价是结果里没有**字数 / 在读 / 最新章**（列表里这几项就不显示）。

> **说明**：扫码登录在子进程中执行网络请求，UI 不卡顿；二维码显示期间可随时取消。

## 配置说明

v2.4.0 起**无需为正文/段评配置任何账号**——设备身份自动注册，段评走官方 commentapi 协议。唯一需要登录的是扫码（书架/进度同步）。

可将 `config.example.lua` 复制一份改名为 `config.lua`，按需修改 Cookie 保底、进度同步与缓存偏好：

```lua
return {
    -- 进度同步
    sync = {
        pull_on_open = true,         -- 打开书籍时拉取云端进度
        upload_on_close = true,      -- 关闭书籍时上传进度
        upload_interval_minutes = 3, -- 阅读中定期上传的间隔（分钟），0 = 关闭
    },

    -- 缓存设置
    cache = {
        download_book_images = true,
        pre_download_chapters = 3,        -- 预下载章节数（0 = 关闭预下载）
        request_interval = 1.0,           -- 批量下载的章间隔（秒），0 = 完全关闭节流
        request_interval_jitter = 0.6,    -- 章间隔上叠加的随机抖动上限（秒），0 = 不抖
        request_batch_size = 20,          -- 每多少章长休一次，0 = 关闭长休
        request_batch_rest = 6.0,         -- 长休时长（秒）
    },

    -- 书架排序（也可在书架左上角菜单里点选；菜单选择优先于这里）
    shelf = {
        sort_order = "last_read",  -- last_read | title | progress | shelf_order
        sort_asc = false,          -- 留空 / nil = 用该排序键的默认方向
    },
}
```

> 旧版本 config.lua 里的 `qingtian` / `dahuilang` 配置段已无消费方，留着也不会生效，可自行删除。

## 使用指南

### 首次使用

1. **安装插件**：将 `fanqie.koplugin` 放入 KOReader 的 `plugins/` 目录
2. **重启 KOReader**
3. **扫码登录**：菜单 → 番茄小说 → 扫码登录，用番茄小说 App 扫描二维码
4. **进入书架**：登录成功后，菜单 → 番茄小说 → 书架

> 正文与段评无需任何配置，设备身份自动注册。

### 书架操作

- **点击书籍**：打开书籍详情页面
- **左上角菜单图标**：点击弹出操作菜单（刷新书架 / 排序方式 / 搜索 / **显示方式**），刷新时动态更新内容无闪烁
- **显示方式**：列表 / 3×3 / 3×4 / 4×3 / 4×4 / 自定义列×行…（行填 0 或不填 = 自动）。当场生效并记住
- **条目信息**：**书名 + 作者 · 连载状态 · 章节进度**。状态标签是 **更新 / 已完结 / 已断更 / 连载中**
  （「更新」= 上次阅读之后作者又更新了新章节）；章节进度是 `122/256 章`，
  从没读过则显示 `未读 256 章`（就是「还有多少没读」）；两者缺一就不显示那一段。
  > **没有进度条** —— 一条没有刻度的细条信息量不如直接写章数；「按阅读进度排序」仍然可用。
- **长按书籍**：显示操作菜单（开始阅读、章节目录、清空缓存）
- **排序**：默认按最后阅读时间倒序。菜单里可选「按书名（正序）/ 按阅读进度 / 按加入书架」，    
  **再点一次当前排序键即翻转正/倒序**（当前项标 ✓）；选择会持久化，跨次进入仍是它
- **搜索**：菜单 → 搜索，输入书名或作者关键字（大小写不敏感、按字面子串匹配），    
  标题栏显示 `[关键字]`；留空即清除筛选。无匹配时保留原列表并提示，不会把菜单清空

### 书城浏览

路径：菜单 → 番茄小说 → 书城（书架与阅读中菜单里都有）

- **直达书库**：点开书城**直接就是书列表**（默认男频 · 全部分类，记住上次频道），
  不用再一层层选。列表顶部一排 **tab：男频 | 女频 | 榜单 | 搜索**
  —— 点男频/女频**原地换频道**（不重开菜单；换频道会回落「全部分类」），
  「榜单」「搜索」一键直达
- **tab 下方筛选行**：**排序：xx ▾** / **状态：xx ▾** / **分类：xx ▾** —— 三个**等宽下拉胶囊**
  平铺一行（宽度按屏宽等分，最小 48px 兜底），文案实时跟着当前筛选走；点一下弹选择器，
  选完列表原地刷新。分类弹**一层**选择器（带「── 主分类（19）──」等**分组分隔头**、
  每页 17 条，其他组带「主题·」「角色·」等前缀）。
  **选择器两种形态**：条目少的（排序 3 / 状态 3 / 性别 2 / 分类浏览 2~3 / 换榜别 3~5）
  直接弹一个**小窗**（居中、点窗外或按返回就关，末尾有「取消」）；条目多的
  （排行榜 30 条、分类 150+ 条）才开**全屏列表** —— 只有全屏那个能翻页、能放分组分隔头，
  150 多条塞进小窗会变成十几屏扫不动的长串。
  **交互模型统一**：tab = 「去哪儿」（目的地，黑字 + 下划线）；筛选行 = 「点了会弹东西」
  （等宽描边胶囊 + `▾`）—— 以前筛选藏在左上角操作框里、和 tab 两套路子，现在一眼分得清
- **排行榜**：最近更新榜 ⇄ 推荐榜 ⇄ **巅峰榜**（tab 原地切，巅峰榜固定 30 本全站总榜、
  明文书名 + 封面 + 名次徽章）；**男频/女频原创榜**：阅读榜 ⇄ 新书榜
  （tab 原地切）；榜单菜单的筛选行是 **性别 ▾ / 分类 ▾ / 榜单 ▾**，选中后**原地换榜**
  —— 同一个菜单换数据，不重开、返回键行为不变
- **搜索**：tab「搜索」直达输入框（**榜单 / 搜索菜单**的操作框里另有「搜索」/「重新搜索」入口），
  输入书名或作者关键字；排序由番茄服务端决定
- **翻页**：列表**滚到最后一页自动追加**下一页，不需要「下一页」按钮
- **左上角操作框**：只剩「**加载更多（已 N / 共 M）**」「**显示方式：…**」「**重新加载**」
  —— 排序 / 状态 / 分类已全部下沉到筛选行，操作框不再重复一遍
- **三块区域各管什么**（内容**按当前界面现算**，不会出现「tab 换了、筛选行还是上一屏的按钮」）：
  - **tab 栏** = 「去哪儿」（目的地）：书库是「男频 / 女频 / 榜单 / 搜索」，
    原创榜是「阅读榜 / 新书榜」，网页榜是「最近更新 / 推荐榜 / 巅峰榜」
  - **筛选行** = 「这一屏显示什么」：书库是「排序 ▾ / 状态 ▾ / 分类 ▾」，
    原创榜是「性别 ▾ / 分类 ▾ / 榜单 ▾」，榜单菜单是「榜单 ▾」
  - **操作框** = 「动作」：加载更多 / 显示方式 / 重新加载（榜单与搜索菜单里多一个「搜索」/「重新搜索」）
- **显示方式**：列表 / 3×3 / 3×4 / 4×3 / 4×4 / 自定义列×行…；书城的档位与书架**各记各的**
- **书籍详情**：点任意一本书 → 详情页显示 书名 / 作者 / 分类 / 字数 / 阅读数 / 状态 / 简介，并提供
  - **加入书架 / 移出书架**：走官方书架接口；成功后书架缓存自动失效，回到书架即可看到。
    🔴 **只给一颗、且方向按实际状态定**：书城详情先 `shelf_check` 再决定给哪颗；
    阅读界面菜单的文案由**同步书架快照**给出（在架「移出书架」/ 不在架「加入书架」，
    判不出来时乐观显示「加入书架」——加入可逆、移出是破坏性的），点击后再 `shelf_check` 复核
  - **读完自动问一句**：不在书架的书，离开阅读（回文件管理器 / 关闭阅读界面）时提示
    「《xx》还没加入书架，要加入吗？」。**切章 / 换书不算离开**（不会打扰）；
    同一本书只问一次（进程内节流）；**状态未知时不猜** —— 先本地补书架缓存、必要时查一次
    `shelf_check`，查不到（离线）就静默跳过
  - **开始阅读 / 章节目录 / 下载**：与书架里的书籍操作完全一致
- **书籍状态**：列表第二行显示「更新于 2026-10-13 · 共 300 章」。状态标签（连载中 / 已完结 / 已断更）
  需要登录后经 `POST /api/bookshelf/multidetail` 增强 —— 列表**先渲染、后增强**（原地替换不闪屏），
  未登录或接口失败时**静默降级**，只显示书库接口自带的分类状态

> **说明**
>
> - 书城走番茄小说**网页版接口**，**免登录即可浏览**；但「加入书架」需要已登录，
>   未登录会提示先扫码登录（服务端返回 `101108 无用户信息`）。
> - **「这本书在不在书架里」怎么判断**：用 `bookshelf/check` 接口（带 `book_id`，
>   在架回 `data=1`、不在架回 `data=0`，只有 39 字节）。**不要**拿 `bookshelf/check` 不带参数的结果
>   （那是 `100103 book_id 无效` 的报错），也**不要**拿 `multidetail` 判断 ——
>   它连不在书架的书也能查。更不要为此拉整个书架名单（24.7 KB）。
>   加入/移出本身是**幂等**的：不在书架时调 delete 一样回成功，
>   所以「操作成功」不能反推「原本在书架」。
> - 书城只提供书目与简介，正文与段评仍走官方 App 协议，**不影响既有阅读链路**。
> - 封面缓存在 `<下载目录>/store_covers/`，文件名按 `book_id`（书库接口的书名是混淆码位解码来的，
>   可能含 `/`、`:` 等非法字符，不能拿来当文件名）。再次打开书城会直接复用磁盘缓存，不重复下载。

### 阅读操作

- **点击左侧**：上一页
- **点击右侧**：下一页
- **点击中间**：打开菜单
- **章节开头向前翻页**：自动跳转到上一章
- **章节结尾向后翻页**：自动跳转到下一章
- **章节最后再翻一次**：不会弹 KOReader 的「已到文档末尾」框（原因见下方 Q&A），
  已经是最后一章时会提示「已经是最后一章了」

**菜单 → 番茄小说 →「书籍信息」**：当前这本书的一屏详情 —— 书名 / 作者 / 分类 / 字数 /
阅读人数 / 连载状态 / 总章数 / 剩余未读 / 最近阅读 / 加入书架时间 / 本地缓存章数 / 简介全文，
可滚动。数据**全部取自本地**（内存里的完整记录 → 从文档路径反推书号 → 用本地书架缓存补全），
所以随点随开、不会卡在网络等待上；实在判不出是哪本书时会明说，不会弹一个空页。

### 段评功能

1. **开启段评**：菜单 → 番茄小说 → 设置 → 段评显示（持久开关，重启后保持状态）
2. **查看段评**：正文中看到段评数字（如 `47`），点击即可查看段评详情
3. **段评详情**：可滚动的评论列表（头行 / 正文 / **图片内嵌**），底部按钮固定两行
4. **展开回复**：两种方式，随便挑
   - **点某一条**：点该条评论的**头行或正文** → 只展开/收起**那一条**
     （v2.16.8 起头行**不再写**「`［展开 N 条回复］`/`［收起］`」标记，回复数就在头行的「回复N」里）
   - 已经展开又还有剩余时，点正文下方那行「**… 还有 N 条回复（点这行继续加载）**」→ 只**继续加载**，
     不会把整条收起来
   - ~~一键全开~~：v2.16.8 起**移除了底部「展开全部回复」批量按钮**（单条点头行已够用，
     批量开关还占掉一整行按钮位）
   - 多级回复按**缩进**显示层级（每级一个全角空格，最多 4 级），被回复者以「回复 某某」标明
   - 「继续加载」单次最多取 20 条**回复**，还有剩余时可继续（最多 5 页 / 100 条）
   - 展开/收起本身**不发网络请求**（只有「继续加载」才请求）；已取到的页会缓存，再次展开零请求
   - 没有回复的评论点不动（不会白白发一次请求）
   - ⚠️ 早于 v2.8.0 是「每条评论一颗 `N ▶M` 按钮」，一页 20 条评论 + 回复 + 图片能爆出几十个按钮；
     现已收敛为**固定 2 行**，按钮数不随评论数增长
   - v2.16.8 起**标题栏不再显示**「段评 X/Y (共Z条)」（翻到第几页的「第X/Y页」指示保留）
5. **段评图片**：评论里的图**自动下载后直接显示在评论下方**（下完一张就刷新一张，滚动位置不跳；
   v2.16.9 起**按图片真实比例渲染**，不再有正方形兜底框的留白）。
   **点图直接全屏查看**（v2.16.9 起不再有「段评图片 N/M」标题栏弹窗——原尺寸 / 旋转 / 关闭
   按钮**点一下屏幕**即呼出；图片加载中时点那行「（图N：正在后台加载…）」也一样，
   会当场下载并打开）；不可显示的图（HEIC 且转码不认）点了只会提示格式问题，所以**不给点**。
   WebP（`.awebp`，平台表情/动图）直接渲染；**HEIC（iPhone 上传的原图）由服务端转码成 WebP 后再下载**，
   本机无 HEVC 解码器也能正常显示（见下方「HEIC 图片怎么处理」）。
   实在转不了的（转码服务不认的路径）会如实显示「（XX 图片，本设备无法显示）」而不是静默丢图。
   下载下来的图片**有有效期**（v2.16.7 起，默认 **1 小时**，档位 10 / 30 / 60 分钟 /
   3 小时 / 永久，见缓存管理 → 评论图片有效期）：过期的图自动重下覆盖，
   打开段评时每小时最多自动清一次过期文件；也可在缓存管理里一键「清空评论缓存」。
6. **关闭段评**：菜单 → 番茄小说 → 设置 → 段评显示（再次点击切换）
7. **重新获取本章节**：段评开启后，点击「重新获取本章节」会带段评数据重新下载当前章节

> **说明**：段评通过官方 commentapi 协议获取，所有章节通用，不再依赖特定书源。
>
> **HEIC 图片怎么处理**：设备端没有 HEVC 解码器，所以转码只能在**服务端**做。
> 番茄图片 CDN 支持按 URL 后缀实时转码，但**签名 URL 的路径整体被签名覆盖**（改动任何一段都回 403）。
> 做法：换到**同路径的无签名 CDN**（`p3-novel.byteimg.com`）并套公共模板
> `~tplv-1yzifmftcy-expand:` + `<宽>:0:0.webp`，服务端实时输出 WebP（默认宽 800）。
> 只对 `tos-cn-i-*` 对象桶与 `img/novel-static` 路径生效，其余路径原样不动。
> 附带好处：转出来的地址**不带签名**，不再受 `x-expires`（约 1 个月）限制。

### 目录操作

- **打开目录**：自动跳转到当前阅读章节所在页面，进入阅读时静默刷新获取新章节
- **点击章节**：跳转到对应章节
- **左上角菜单图标**：点击弹出操作菜单（刷新目录），保持当前页码
- **缓存标记**：已下载的章节显示 ✓ 标记

### 下载管理

路径：菜单 → 番茄小说 → 下载管理

- **查看进度**：当前下载任务显示实时进度条和章节信息
- **取消下载**：点击「取消下载」**立刻**中止 —— 连正在下载的那一章一起掐掉，
  不必等它跑完（图集/漫画单章动辄 1~5 分钟）；被取消的任务也会记进历史
- **后台运行**：下载进度对话框可关闭，下载在后台继续
- **历史记录**：显示最近 10 条下载记录（完成/中断/取消）
- **清空历史**：点击「清空历史记录」清除所有历史

> **说明**：下载状态持久化到本地，即使 KOReader 退出重启，历史记录依然保留。未完成的下载会标记为「中断」。

### 离线阅读

- **书架离线**：书架数据自动缓存，无网络时显示缓存内容，刷新失败保留旧数据
- **章节离线**：已下载的章节无网络也可阅读
- **自动定位**：离线打开书籍时，从上次阅读的章节开始（书架数据中的进度）
- **两层缓存**：内存主源 + 文件后备，重复显示书架/目录零文件IO，Kindle弱设备流畅运行
- **智能回退**：Cookie过期/网络失败时自动回退到文件缓存，不丢失已有数据

## ⚠️ 重要声明

### 接口说明

- **正文/段评/目录**：番茄 App 端 reading / commentapi 协议（`api5-normal-sinfonlinec.fqnovel.com`）。正文请求需先在本机生成设备画像、向 `log.snssdk.com` 注册换取 `device_id`/`install_id`，再经四神签名（X-Khronos / X-Ladon / X-Helios / X-Argus）请求密文并本地 AES 解密。设备身份每台设备独立生成并持久化，不复用他人身份；无需番茄账号登录。
- **书架/进度**：番茄网页接口，扫码登录获取 Cookie。

### 使用规范

1. **请勿一次性下载全本书**：插件默认仅预下载 3 章，请保持此设置
2. **请勿滥用接口**：频繁请求可能导致 IP 被封禁
3. **请合理阅读**：建议每天阅读时长不超过 2 小时，保护视力

## 常见问题

### Q: 书架显示为空？

A: 请检查是否已扫码登录。菜单 → 番茄小说 → 扫码登录，用番茄小说 App 扫码。Cookie 过期会提示重新登录，重新扫码即可。

### Q: 章节内容获取失败？

A: 官方 App 协议依赖设备身份注册（`log.snssdk.com`）与签名网关（`api5-normal-sinfonlinec.fqnovel.com`），请检查网络是否可访问这两个域名；设备身份被风控时会提示空响应，可清除 KOReader 设置里 `fanqie.lua` 的 `reading_device` 后重试（会自动重新注册）。

### Q: 段评不显示？

A: 请确保：1) 菜单 → 番茄小说 → 设置 → 「段评显示」开关已开启；2) 点击「重新获取本章节」带段评数据重新下载当前章节（旧缓存章节不带气泡）。v2.4.0 起旧版大灰狼书源的段评缓存（ident 含 czyl.cf）不再支持，重新获取即可。

### Q: 点击段评数字没反应？

A: 请确保已更新到最新版本，并重启 KOReader 使补丁生效。

### Q: 点击段评数字后提示「段评获取失败: ...」？

A: 弹窗现在会直接显示服务端返回的原因，常见的有两类：

- **`空响应（设备身份可能被风控）` / `HTTP 4xx`**：签名网关拒绝了这次请求。段评列表是三个段评接口里唯一的 POST，    
  被风控时服务端回的是 **200 空响应**（不是错误码）。等一会儿重试，或在「设置」里清除设备身份后重试。
- **`code=110001 msg=未知异常`**：请求带了不该带的 `x-ss-stub` 头（协议要求段评 POST 绝不携带）。

### Q: 点击段评提示「本条段评共 N 条，服务端未返回内容，请稍后重试」？

A: 气泡上的条数来自 `idea/list` 统计，而弹窗里的列表来自 `comment/list`。两者不一致说明列表这次拿到了空结果，  
通常是短时限流或网络抖动，稍后重试即可。若反复出现，请把 KOReader 日志里 `[段评]` 开头的行反馈过来。

### Q: 阅读进度不同步？

A: 先确认网络正常。上传时机（读到哪就传到哪）：

- **阅读中每 3 分钟自动上传一次**（设置 → 阅读中定期上传进度，可选 关闭 / 1 / 3 / 5 / 10 分钟）；
  只在进度有前进时才真的发包，不会空打接口
- 翻到章末 / 关闭文档 / 打开目录时立即上传
- 上传失败会进「待传队列」：进书、切章时自动重试；**退出 KOReader 时还会落盘**，下次打开继续补
- 切章时补发的是**刚读完那一章**的进度。每章是一个独立的 html，切章等于「关掉旧文档 + 打开新文档」，
  所以「关闭时上传」在切章时也会触发一次 —— 这是预期行为，同一章同一进度只发一次，不会重复上传

拉取侧：进入阅读自动拉取云端进度（设置 → 读取进度同步可关）。

### Q: 封面不显示？

A: 封面是异步下载的，首次打开书架时需要等待一段时间。如果长时间不显示，请检查网络连接。

v2.6.0 起，插件会把番茄接口返回的**签名**封面地址统一收敛为无签名 CDN 地址，签名过期不再导致 403 空白。  
若仍有个别书封面空白，多半是网络被拦截或该书封面本身已下架。

### Q: 封面缓存占地方吗？能清吗？

A: 封面缓存有**有效期**（设置 → 封面缓存，默认 **3 天**，可选 3 / 7 / 9 / 30 天或「永久」）。
（v2.15.0 起提供该设置，v2.16.0 起默认值由 30 天改为 3 天。）
过期的封面会被当没有、重新下一张覆盖；此外**每天自动清一次**过期封面（一天最多一次，不会反复扫盘）。

同一个入口能看到当前占用（「共 N 张 · X MB」），也能手动「清理过期封面」或「清空封面缓存」。

> ⚠️ 清理**只动封面目录里这一层的图片**，不递归 —— 封面目录旁边就是整本书的章节缓存。
> 想彻底不失效就把有效期设成「永久」，那时清理什么都不删。

### Q: 段评图片缓存占地方吗？能清吗？

A: 有**有效期**（缓存管理 → 评论图片有效期，默认 **1 小时**，可选 10 / 30 / 60 分钟 /
3 小时 /「永久」）。过期的图片下次显示时自动重下覆盖，打开段评时**每小时最多一次**
自动清理过期文件；缓存管理里的「清空评论缓存」可以一次全删（含内存里的段评页缓存）。
段评数据本身只存在内存里，退出即失效，落盘的只有这些图片。

### Q: 书架/目录刷新后数据没变？

A: v2.2.0 采用「刷新成功才更新缓存」策略。如果网络失败/Cookie过期，会保留旧缓存并提示"刷新失败，显示缓存数据"。请确保网络正常且Cookie未过期，再点击左上角菜单图标 → 刷新。

### Q: 书城提示「书城加载失败：...空响应...」？

A: 书城走的是番茄网页版接口。服务端有时会返回 **HTTP 200 但响应体 0 字节**（限流或接口临时下线）。  
插件特意把这种情况和「真的没有数据」区分开并明确报出来，**不会**显示一个空书城。  
稍后再试即可；若长期如此，说明该接口已变更，请反馈。

### Q: 书城的筛选（排序 / 状态 / 分类 ▾）为什么有时弹小窗、有时跳整页列表？

A: 看**条目多少**。排序(3) / 状态(3) / 性别(2) / 分类浏览(2~3) / 换榜别(3~5) 只有几项，
弹一个小窗就够（居中、点窗外或按返回关闭）；**排行榜入口(30 条)** 与 **分类选择器
(男频 154 / 女频 182 条)** 条目多，只有全屏列表能**翻页**和放**分组分隔头**
（「── 主分类（21）──」这类），塞进小窗会变成十几屏扫不动的长串。

这不是偷懒：koreader **没有「下拉浮层」这种原生控件** —— 能弹小窗的 `ButtonDialog`
只有「一整条长滚动」，没有分页也没有分组头；能翻页 + 分组的只有 `Menu`，而它不传尺寸时
就是整屏。所以两边各取所长：**阈值 8 项**，带分组分隔头的一律走全屏。

### Q: 读番茄小说时，读完最后一页再往后翻，那个「已到文档末尾」的框呢？

A: 插件在读番茄章节期间把它**临时关掉**了 —— 读完只会跳到下一章，已经是最后一章时提示
「已经是最后一章了」。

原因是**一章就是一个 html 文件**：在 KOReader 眼里「读完一章」＝「读完一本书」，于是它会按
全局设置「到达文档末尾时的操作」（默认「弹窗询问」）弹框。而这个框来自 `ReaderStatus`，
它注册得**比插件早**，事件又是按注册顺序分发的（`propagateEvent` 正序遍历，第一个返回 true 的
就把事件截住）—— 插件抢不到，只能让那一项「什么都不做」。

做法：打开番茄章节时把该设置改成「什么都不做」（`ReaderStatus` 对这个值没有分支，且它返回
nil、不截断事件，所以插件的自动下一章照旧），**离开时把你原来的值还原**。所以你的设置没有被
永久改动，读 epub 等其它书时行为完全不变；如果你在阅读中途自己去设置里改过，插件离开时会
**让路**、不覆盖你的选择。

### Q: 段评里的图片加载出来的时候，屏幕会闪一下吗？

A: 现在不会了。

图片是逐张下载、下完一张回填一张的。以前每次回填都会**整屏重绘一次** —— 现象就是
「图片一加载屏幕就闪一下」，一页好几张图就闪好几下。根因是回填时重建完内容树要标脏重绘，
而传给 KOReader 的「刷新区域」取早了：控件的位置与尺寸（`dimen`）是**上一次绘制**留下
的产物，新造出来的树在画出来之前根本没有这个值，于是传进去的是空值 —— 而 KOReader
对空区域的处理是**补成整屏**（顺带还会累计全刷计数，攒够了就升格成一次真正的黑闪）。

现在改成「**等这一帧画完再取区域**」，只重画评论区那个框；而且新旧框一起覆盖
（框是居中的，图片插进来会让框变高 ⇒ 只刷新框会在旧框边缘留一圈残影）。

### Q: 书城的书名/作者显示成方块或乱码？

A: 番茄网页接口把部分文案用私用区码位替换过，插件内置了 356/372 条映射（约 95.7%），  
绝大多数书籍能正常显示。若仍出现零星方块，说明命中了未收录的码位，日志里会有  
`[warn] ... PUA 未映射码位`，把日志反馈即可补表。

### v2.16.14

**评论底部拆成两行：统计灰、操作黑**

用户反馈：「单条评论最下面那一行，里面时间、回复数、点赞数啥的应该是灰色，
展开 m 条回复应该是白色，展开 n 条回复应该单独开一行」。

- **统计行（灰）**只放信息：`赞N · 回复N  时间`；
- **折叠行（黑）单独一行**：`展开 N 条回复` / `收起回复`，紧贴在回复树上方，
  点它仍是展开/收起（整行可点，交互没变）；
- **「… 还有 N 条回复」也改黑色**：它同样是可点的操作行，以前跟统计行一个灰度，
  分不清哪行能点。现在规则统一：**灰 = 信息，黑 = 可操作**。

为什么是「黑」而不是「白白的一行」：KOReader 的夜间模式是整屏 framebuffer 反色，
写黑字白天显示黑、夜间被反成白；真按「夜间白字」写分支，夜里会反成黑字直接看不见。

### v2.16.13

**修「缓存管理一打开就闪退」+ 回复正文与一级评论同色**

- **闪退根因**：缓存管理菜单的第一行是「缓存统计: N 本书, N 章节, X MB」，
  它调用 `Settings:get_cache_stats()` —— 该函数**双层裸遍历**缓存目录
  （145 本书 × 每章一个 html），任何一次 `lfs.dir` / `lfs.attributes` 失败
  （目录被删到一半、权限、坏项、遍历途中被外部改动）都会**抛错**；
  而菜单构建期抛错 = 整个子菜单打不开，在设备上就是「点开缓存管理直接闪退」，
  且没有任何可读提示（错误只进 crash.log）。
  - 现在遍历改为**尽力而为**：顶层与每本书各自 pcall，读不了的书跳过、
    已统计到的部分照常显示；彻底失败时第一行显示
    「缓存统计: 暂不可用（读取缓存目录失败）」而不是崩菜单。
  - 每个占用文案（`text_func`）也各自兜底，单项失败只影响该项
    （显示「（读取占用失败）」），并把真实原因写进 `fanqie.log` 的 WARN。
  - 菜单整体再加一层 pcall 闸门：真出意外时显示「缓存管理加载失败：<原因>」，
    不会再闪退。
- **顺带修一处统计口径**：`covers/`、`store_covers/`、`comment_images/` 都建在
  下载目录里，以前会被当成「书」各算一本（书数虚高、字节数也偏大）。现在跳过。
- **回复正文与一级评论同色**：以前二级回复的正文是深灰（`COLOR_DARK_GRAY`），
  墨水屏上看着像「已读/禁用」，用户反馈「二级评论和一级评论不是一个颜色」。
  层次改由**左缩进 + 小一号字号 + 头行加粗**区分，正文一律纯黑。

### v2.16.12

**修「评论能显示、回复只有一大块空白」—— 回复块从未被画出来过**

- **根因**：v2.16.0 重写评论视图时，回复块的左缩进包装用了
  `HorizontalGroup{ align = "left" }` —— 而 KOReader 的 `HorizontalGroup` 只认
  `center / top / bottom`，`left` 是 `VerticalGroup` 的词汇。非法对齐走进
  `paintTo` 的 else 分支：**一个像素都不画**，但尺寸照算、高度照占 ——

  （fanqie.log 里零报错）；回归桩的 `HorizontalGroup` 没有实现绘制语义，
  非法对齐也照画不误 ⇒ 假绿。本版给桩补上真实绘制语义（非法对齐=零绘制），
  并新增 8 条断言：树内对齐全部合法、回复文本必须真被"画"到、源码守卫
  （对齐必须是 top 且不得再出现 left/right）。
- 修复：对齐改为 **`top`**（左垫片高度为 0，内容从行顶开始 = 左缩进原意）。
- 受影响范围：v2.16.0 ~ v2.16.11 的**所有回复块**（含展开的二级回复）。

### v2.16.3

**修「书城搜索一直加载失败」的真因：搜索接口要的是风控标识 `s_v_web_id`，而不是登录态 —— 且手动 Cookie 兜底在已登录时形同虚设**

- **修**：**搜索接口只认 `s_v_web_id`**（番茄 web 风控指纹 cookie）。实测二分定位：
  只带 `s_v_web_id` 一个键 → 11 KB / 10 条正常；只带 `sessionid`（登录态）→ 0 字节；
  只带 `ttwid` → 0 字节；不带 → 0 字节；**伪造值同样 0 字节**（服务端只认它认可的真值）。
  这就解释了那个长期矛盾：**书架只认登录态所以正常，搜索认风控标识所以恒失败**。
- **修**：**手动 Cookie 兜底在「已登录」时完全不生效**（真正的坑）。旧逻辑发现本地已有
  扫码 cookie 就**整段跳过** `config.cookie_string` ⇒ 用户把浏览器 Cookie 填进 `config.lua`
  也**一点不生效**，而扫码链路又拿不到 `s_v_web_id`（登录页 / 二维码接口 / 首页 / 搜索页

  扫码结果**，并在「重新加载配置文件」后如实提示「已补入本地缺失的 Cookie: s_v_web_id」。
- **修**：**错误分类由二分改三分**（0 字节的三种成因处置相反）：没带 Cookie → 提示登录；
  带 Cookie 但**缺** `s_v_web_id` → 新增 `kind=risk`，点名 `s_v_web_id` 并给出可执行处置
  （填 `config.lua` 的 `cookie_string` → 重新加载配置）；两者都齐 → 才如实报限流。
  归到 `auth` 会让用户去重复扫码，而**扫码本来就拿不到它**，只会白折腾。
- **更正（v2.16.2 段里那句结论是错的）**：v2.16.2 的说明写着「搜索接口只要请求里带 Cookie 头

  得出的误判。用**插件自己的头组合**（UA / `Accept-Encoding: identity` / `Connection` /
  `Referer` 全照抄 `Client:request`）重放后，假 cookie 一律 0 字节。真正起作用的是 `s_v_web_id`。
- **验证**：`_verify_shelf_sort_search.py` 新增 B2 段 7 项（含 NEGATIVE：旧代码下必然红）；
  `_verify_client_cookie_flag.py` 28 项（新增三态 message 与 `has_sv_web_id` 事实断言）；
  `_verify_store.py` 235 项（新增 `kind=risk` 4 项）；`_mutate_sv_web_id.py` 12 个变异体全部被抓。
- **怎么用**：把浏览器里的完整 Cookie 填进 `config.lua` 的 `cookie_string` →
  菜单「重新加载配置文件」→ 看到「已补入本地缺失的 Cookie: s_v_web_id」即为生效。

**修「明明已登录，书城搜索却提示『请先登录番茄账号（书城部分接口需要 Cookie）』」：0 字节响应不再一律当成没登录**

### v2.9.0

**🔎 书城分页：确认接口没下线，并把翻页做得看得见**

用户给的浏览器 curl 里带 `page_index=1` —— 书库接口本来就是**分页**的。顺手把旧结论复核了一遍，
三处都改了：

- **更正上一版的一条错误结论**：`/api/author/library/book_list/v0/` **没有下线**。
